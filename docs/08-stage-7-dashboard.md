# Stage 7 — Dashboard

**Document 08 · Estimated time: 0.5–1 day · Cost: $0**

One HTML page, generated by a Code node, served through a Webhook. No framework, no build step, no login, no navigation.

The reason to build it is not aesthetics. It is that the dashboard converts an abstract capability — *"it reads certificates"* — into a felt absence — *"I don't have this."* A prospect looking at eighteen of **their own** vendor names with four rows grey and two red understands their exposure faster than any explanation you could give. Without it you are showing JSON in an execution log, and you look like a developer rather than a supplier.

**Gate:** a scan of the rendered HTML for the forbidden words returns zero hits.

---

## 7.1 Why hand-built and not off the shelf

Rejected: NocoDB, Metabase, Appsmith, EspoCRM, Retool.

Each gives you filtering and sorting you do not need for a four-minute demo, and takes away the thing you do need: a screen that looks like a product someone built for property managers. A single HTML page has no licence question, no extra container to keep alive on stage, and no chance of an unfamiliar admin UI surprising you mid-call. **In a demo, controlling every pixel is worth more than any feature these give you.**

It is also roughly 200 lines of code, which is less than the time you would spend configuring any of them.

### N2 · `IF — Token Valid`

```
{{ $json.query.k }}  equals  {{ $('Postgres — Load Config').first().json.config.dashboard_token }}
```

A shared token in a query string is thin security, and it is the right amount here. The page contains vendor names, carrier names, policy numbers, and dates — B2B business records, no tenant data, no consumer personal information, no financial details. The token stops a URL guesser and a search crawler, which is the actual threat.

Do not put the token in the URL you screen-share. Open the tab before the call.

**Production hardens this**: Caddy `basic_auth` on the `/webhook/coi*` path, or an n8n Header Auth credential on the webhook. Both are five-minute changes; neither belongs in a demo where you are the only viewer.

  if (n >= 1_000_000) return `$${(n / 1_000_000).toFixed(n % 1_000_000 ? 1 : 0)}M`;
  if (n >= 1_000)     return `$${Math.round(n / 1_000)}k`;

};

 * The status string. Every branch returns a fact about a date or a document.
 * No branch returns a judgement. If you find yourself wanting to add one,
 * that is the feature request that ends the business — see docs/00.
 */
function statusText(r) {
  if (r.certificate_status === 'CANCELLED')   return 'Recorded as cancelled';
  if (r.certificate_status === 'NON_RENEWED') return 'Recorded as not renewed';
  if (!r.certificate_id)                      return 'No certificate on file';
  if (r.certificate_status === 'NEEDS_REVIEW') return 'Needs review';
  if (r.earliest_expiration == null)          return 'Needs review';

  const d = Number(r.days_to_expiry);
  if (d < 0)  return `Expired ${Math.abs(d)} day${Math.abs(d) === 1 ? '' : 's'} ago`;
  if (d === 0) return 'Expires today';
  if (d <= 60) return `Expires in ${d} day${d === 1 ? '' : 's'}`;
  return `Current until ${fmtDate(r.earliest_expiration)}`;
}

  HOLDER_MISMATCH:           'Certificate names a different entity',

  NO_WC_LINE:                'No workers compensation line',

  POSSIBLE_DUPLICATE_VENDOR: 'Name is close to an existing vendor — needs a person',
  DATE_INVERTED:             'Expiration date precedes the effective date',
  DATE_IMPLAUSIBLE:          'A date is far outside the expected range',
  DATE_UNPARSEABLE:          'A date could not be read',
  LOW_CONFIDENCE:            'Low confidence reading this document',
  OLDER_THAN_ON_FILE:        'Older than the certificate already on file',
};

// ─── Header counts. Computed, never hardcoded — you will re-run the demo
//     and they must change. ───

  total:       rows.length,
  never:       rows.filter((r) => r.bucket === 'NEVER_RECEIVED').length,
  expired:     rows.filter((r) => r.colour === 'red' && r.certificate_id).length,
  expiring:    rows.filter((r) => r.colour === 'amber' && r.certificate_status !== 'NEEDS_REVIEW').length,
  review:      rows.filter((r) => r.certificate_status === 'NEEDS_REVIEW').length,
  gaps:        rows.filter((r) => Number(r.coverage_gap_days) > 0).length,
  paused:      rows.filter((r) => r.chase_paused).length,
};

const pill = (n, label, cls) =>
  n > 0 ? `<span class="pill ${cls}"><b>${n}</b> ${esc(label)}</span>` : '';

// ─── Rows ───
const body = rows.map((r) => {
  const flags = Array.isArray(r.validation_flags) ? r.validation_flags : [];
  const notes = [];

  for (const f of flags) {
    const label = FLAG_LABELS[f.code] || f.code;
    const cls = f.code === 'COVERAGE_GAP' ? 'note gap' : 'note';
    notes.push(`<div class="${cls}">${esc(label)}${f.detail ? ` — ${esc(f.detail)}` : ''}</div>`);
  }

  if (r.confidence_reason && r.certificate_status === 'NEEDS_REVIEW') {
    notes.push(`<div class="note">${esc(r.confidence_reason)}</div>`);
  }

  // Cancellation-notice wording renders NEUTRAL GREY. Never green, never a
  // tick. It is a sentence on a form, not a protection: since the 2010 ACORD
  // revision, notice runs to the insured under the policy terms, not to the
  // certificate holder.
  if (r.cancellation_notice_wording) {
    notes.push(`<div class="note neutral" title="${esc(r.cancellation_notice_wording)}">` +
               `Certificate states notice of cancellation wording</div>`);
  }

  if (r.chase_paused) {
    notes.push(`<div class="note neutral">Automated reminders paused — with a person</div>`);
  }

  const pdfLink = r.certificate_id
    ? `<a class="src" target="_blank" rel="noopener" ` +
      `href="/webhook/coi/pdf?id=${r.certificate_id}&k=${esc(cfg.dashboard_token)}">source&nbsp;PDF</a>`

      <td>${esc(r.earliest_insurer ?? '—')}</td>
      <td class="mono">${esc(r.earliest_policy_number ?? '—')}</td>
      <td class="num">${fmtMoney(r.gl_each_occurrence)}</td>
      <td class="status">${esc(statusText(r))}</td>
      <td class="src-cell">${pdfLink}</td>
    </tr>`;
}).join('');

## 7.4 Design rules the template enforces

| Rule | Where |
|---|---|
| Status text is a date fact, never a verdict | `statusText()` — every branch returns a date or a document fact |
| The four forbidden words appear nowhere | Enforced by test, checked in Stage 8 |
| `NEVER_RECEIVED` rows sort to the **top** | `q_dashboard.sql` ORDER BY |
| Every row with a certificate links to its source PDF | `pdfLink` |
| Flags render as a note under the vendor name, not a column | `.note` divs |
| `COVERAGE_GAP` gets its own header count | `counts.gaps`, `pill(..., 'gap')` |
| Cancellation wording renders **neutral grey**, never green | `.note.neutral` |
| Header counts are computed | `counts` object |
| Amber at ≤ 30 days, red at ≤ 0 or `NEEDS_REVIEW`, grey for none | `v_vendor_status.colour` |

### Why `NEVER_RECEIVED` sorts to the top

The vendors you have nothing for are the ones worth looking at first. *"Expiring soon"* is a calendar problem; *"we have never had anything from them"* is a different problem entirely. Four grey rows at the top of an otherwise working register is the picture that sells — and it is also, straightforwardly, the correct priority order.

### Why the footer disclaimer is in the template and not just in the proposal

The dashboard is the artefact a prospect screenshots and forwards to their business partner. That screenshot travels without you, without your scope document, and without the sentence you said on the call about endorsements. Putting the limitation on the page means the caveat travels with the claim.

It also costs you nothing in the demo — nobody reads a footer during a four-minute call — while being the single most useful thing on the page if the screenshot ever ends up in a dispute.

## 7.5 PDF serving

**Never expose `/data/certs` as a static directory.** Path traversal on a webhook parameter is trivially exploitable and there is no reason to accept the risk when a database lookup costs nothing.

### `Webhook — Certificate PDF`

Method `GET` · Path `coi/pdf` · Respond `Using 'Respond to Webhook' Node`

### `Postgres — Lookup Path`

```sql
-- $1 = certificate id from the query string
SELECT c.stored_path, c.original_filename, v.display_name
FROM   certificates c
LEFT   JOIN vendors v ON v.id = c.vendor_id
WHERE  c.id = $1::int
  AND  c.stored_path IS NOT NULL;
```

The path comes from the database, never from the request. The request supplies an integer ID and nothing else. `$1::int` makes a non-numeric input a type error rather than something to sanitise.

### `Read File From Disk`

`n8n-nodes-base.readWriteFile` · Operation `Read File(s) From Disk` · File Selector `={{ $json.stored_path }}` · Settings → On Error `Continue` (missing file → a 404 response, not a crash).

### `Respond to Webhook`

Respond With `Binary` · Response Data Source `Choose Automatically From Input` · Headers:

```
Content-Type: application/pdf
Content-Disposition: inline; filename="{{ $json.original_filename }}"
X-Content-Type-Options: nosniff
```

`inline`, not `attachment` — the PDF opens in a browser tab rather than downloading. During a demo you want a tab you can close, not a file in a downloads folder.

## 7.6 The forbidden-word test

`test/forbidden_words.py`:

```python
#!/usr/bin/env python3
"""
Fetches the rendered dashboard and fails if any forbidden word appears.

This is the automated enforcement of the constraint that defines the product:
the system reports facts about paperwork and never draws conclusions about
coverage. A prompt can drift. A test cannot.
"""
import os, re, sys, urllib.request

BASE = os.environ["N8N_BASE_URL"].rstrip("/")
TOKEN = os.environ["DASHBOARD_TOKEN"]

FORBIDDEN = [
    r"\bcompliant\b", r"\bnon-compliant\b", r"\bcompliance\b",
    r"\bverified\b", r"\bverify\b", r"\bverification\b",
    r"\bcovered\b", r"\bcoverage is\b",
    r"\bapproved\b", r"\bvalid\b", r"\bin good standing\b",
]

# Permitted: the footer explicitly disclaims these. Anchor on the exact
# sentences so the exemption cannot silently widen.
ALLOWED_CONTEXTS = [
    "It does not assess insurance coverage",
    "cannot confirm that an endorsement exists",
]

def main() -> int:
    url = f"{BASE}/webhook/coi?k={TOKEN}"
    with urllib.request.urlopen(url, timeout=30) as r:
        html = r.read().decode("utf-8")

    scan = html
    for phrase in ALLOWED_CONTEXTS:
        scan = scan.replace(phrase, "")

    failures = []
    for pat in FORBIDDEN:
        for m in re.finditer(pat, scan, re.I):
            s, e = max(0, m.start() - 70), min(len(scan), m.end() + 70)
            failures.append(f"  {m.group(0)!r}\n    …{scan[s:e].strip()}…")

    if failures:
        print(f"FORBIDDEN WORDS IN DASHBOARD ({len(failures)}):\n")
        print("\n\n".join(failures))
        print("\nThe register states date facts, never verdicts. See docs/00.")
        return 1

    print(f"✓ Dashboard clean — {len(html):,} bytes, no forbidden words")
    return 0

if __name__ == "__main__":
    sys.exit(main())
```
